# Bot Health alert runbook

Все действия сначала read-only. Alert не является командой закрыть/открыть
позицию, повторить order или перезапустить worker. Существующий restart может
повторить свечу: [разбор](restart-safety-review.md). Не менять state.json для
сброса алерта. Рабочие правила сначала paused; инструкции активации —
[этап 3](monitoring-stage3.md).

## heartbeat

Проверить доступность Grafana datasource и свежесть других samples. Если нет всех
метрик — проверить статус и логи существующего Render worker, затем доставку
Grafana Cloud. Если samples свежие, а main timestamp старый — основной поток
может ждать/зависнуть на существующем вызове. Сравнить main age и sample age.
Не запускать вторую копию `bot.py`, не нажимать Restart/Deploy для диагностики.
Если есть Query Error, сначала расследовать datasource: `DatasourceError` не
доказывает остановку бота. При подтверждённой проблеме сообщить владельцу и
согласовать отдельное действие.

## cycle

Расписание обработки — около 15 минут; успешный цикл означает все необходимые
этапы, а не любой проход ожидания. Посмотреть последний success и startup age.
Если это первый запуск без чистого цикла, предусмотрено 25m grace + 5m pending.
Проверить подавленные ошибки API, balance validation, pending confirmations и
ошибки сохранения по существующим логам. Не обходить safeguards, не восстанавливать
старый state и не переотправлять pending entry вручную.

## bybit-errors

Сопоставить operation/category с существующими логами. Считаются SDK calls,
включая существующие read retries; отказы telemetry не создают retries ордера.
Проверить статус Bybit и доступность сети вне торговых действий. Самостоятельно
не вызывать API с торговыми ключами ради теста.

## bybit-critical

За окно 15m минимум 5 ошибок и доля >=25%, pending 2m. Посмотреть, какие операции
отказывают, работает ли heartbeat и есть ли успешные balance/candle markers.
Высокая доля на небольшом числе запросов требует ручной оценки. Не менять risk,
TP/SL, ключи, retries или order confirmation ради устранения алерта.

## disk

Проверить mount/DATA_DIR и реальное свободное место read-only. Порог — 100 MiB,
а не выдуманный процент. NoData по disk может означать отказ измерения.
Не удалять state, backups, логи или каталоги автоматически. План очистки/ротации
сначала согласовать и сохранить актуальную копию состояния.

## export

Проверить свежесть heartbeat/sample и безопасные monitoring warnings. Отказ
экспорта может отображаться после восстановления. Проверять только наличие
секретной env, не раскрывать её. Не печатать env/HTTP headers/ответы с secrets,
не менять флаг мониторинга для проверки: его изменение требует restart.

## dropped

Посмотреть CPU/RAM и ошибки экспортёра. Mailbox bounded/nonblocking: потеря
наблюдения не означает потерю торговой операции, но counters/latency неполны.
Не увеличивать очередь или cardinality в production без отдельного изменения
и проверки памяти. Не делать вывод об отсутствии ордеров только по этой метрике.

## restarts

Сверить process start/uptime, Render Events и источник deployment. Это оценка
наблюдаемых смен, а не полный журнал Render. Невидимые короткие процессы могут
не попасть в неё. Проверить, что работает один worker, без запуска дополнительных
экземпляров. Не проводить новый restart для воспроизведения. Обсудить причину
неожиданных стартов и конкретный план восстановления с владельцем.
